- ## 仅逻辑删除
	- 考虑到用户表中，可能会绑定一些 **未注销用户唯一 (但不保证注销的用户唯一)** 的字段。
		- 比如：手机号、邮箱。
	- 如果直接在这些字段上加 **唯一索引** ，将导致：
		- 注销用户的这些字段的值，不能相同。
		- 注销用户的这些字段的值，不能与未注销用户相同。
	- 此时，可以考虑使用：
		- **条件唯一索引** （MySQL 没有）
		  logseq.order-list-type:: number
			- 只有满足条件的数据，才参与唯一索引的构建。
		- **生成列（Generated Column）** （MySQL 有）
		  logseq.order-list-type:: number
			- 单独在 **生成列** 上建立 **唯一索引** 。
			- ``` sql
			  CREATE TABLE user_account (
			      id BIGINT NOT NULL AUTO_INCREMENT,
			      phone VARCHAR(32) NOT NULL COMMENT '手机号',
			      account_status TINYINT NOT NULL DEFAULT 1
			          COMMENT '1-正常，2-冻结，3-已注销',
			  
			      unique_phone VARCHAR(32)
			          GENERATED ALWAYS AS (
			              CASE
			                  -- 正常、冻结账号仍然占用手机号
			                  WHEN account_status IN (1, 2) THEN phone
			                  -- 注销后释放手机号
			                  ELSE NULL
			              END
			          ) STORED,
			  
			      PRIMARY KEY (id),
			      UNIQUE KEY uk_unique_phone (unique_phone)
			  );
			  ```
- ## 物理删除 + 归档 （一般不推荐）
	- 具体做法：
		- 物理删除原数据
		  logseq.order-list-type:: number
		- 将数据写入归档表中（考虑到需要追溯历史）
		  logseq.order-list-type:: number
- ## 逻辑删除 + 设置唯一字段为 Null + 归档
	- 具体做法：
		- 逻辑删除原数据
		  logseq.order-list-type:: number
		- 将原数据唯一字段值设为 Null
		  logseq.order-list-type:: number
		- 将数据写入归档表（考虑到需要追溯历史）
		  logseq.order-list-type:: number
- ## 认证信息拆分为单独的表
	- 用户信息表 + 多个认证信息表
		- 多个认证信息表：
			- 用户账号密码表
			- 用户手机表
			- 用户小程序账号表
	- 认证信息表中的数据，在用户注销时进行 **物理删除** 就行，因为这些表表示的当前的状态。
	- 如果需要历史数据，则加个归档表就好，记录认证数据的修改历史。
