- ## 什么是幂等性
	- 指 **多次相同请求** 对 **服务端资源** 产生的预期效果，和执行 **一次请求** 一致。
- ## 什么情况下会触发多次请求
	- 重试操作。
	  logseq.order-list-type:: number
		- 网络波动等原因，让用户误以为请求未执行，导致用户在客户端重试。
		  logseq.order-list-type:: number
		- 用户使用工具，先后多次调用请求。
		  logseq.order-list-type:: number
		- 服务端的消息队列、网关等服务，因为超时等原因，自动发起的重试。
		  logseq.order-list-type:: number
	- 并发请求。
	  logseq.order-list-type:: number
		- 用户在一个客户端上迅速多次请求。
		  logseq.order-list-type:: number
		- 用户在多个客户端上并发请求。
		  logseq.order-list-type:: number
		- 用户使用工具，并发调用请求。
		  logseq.order-list-type:: number
- ## 保证幂等性不能仅靠客户端
	- 客户端可以保证用户在一次请求后禁止再次发起请求。
	- 但其他方式可以绕过客户端，触发多次请求。
		- 上述提到的：请求工具 或 服务端自动重试。
	- 所以，幂等性必须要 **服务端** 最终保证。
- ## 数据操作分类
	- 插入类操作。
	  logseq.order-list-type:: number
		- 要依赖业务 **唯一键** 或 **幂等键** ，避免重复创建数据
	- 赋值更新操作。
	  logseq.order-list-type:: number
		- `update set status = 'PAID'`
	- 累加更新操作。
	  logseq.order-list-type:: number
		- `update set balance = balance - 100`
