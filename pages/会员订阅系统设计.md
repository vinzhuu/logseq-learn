- ## 关于周期扣费
	- 需要注意如下几点, 并在签约前明确告知用户:
		- 扣费通知:
		  logseq.order-list-type:: number
			- 扣费前需要下发通知
			  logseq.order-list-type:: number
			- 通知日期固定 (比如到期前 3 天).
			  logseq.order-list-type:: number
			- 通知时间合理 (比如 7:00~22:00)
			  logseq.order-list-type:: number
		- 发起扣费:
		  logseq.order-list-type:: number
			- 扣费日期固定 (比如到期前 1 天).
			  logseq.order-list-type:: number
			- 扣费时间合理 (比如 7:00~22:00)
			  logseq.order-list-type:: number
			- 扣费完成通知 (如 下发短信 或 APP Push)
			  logseq.order-list-type:: number
			- ==扣款失败通知: 扣款失败是否应该告知用户?==
			  logseq.order-list-type:: number
		- 自动解约:
		  logseq.order-list-type:: number
			- 在某些情况, 需要将用户自动续费主动解约.
			- 比如:
				- 第一次扣费失败.
				  logseq.order-list-type:: number
				- 当前扣费周期结束, 仍然扣费失败.
				  logseq.order-list-type:: number
			- 同时应该明确告知用户, 为何发生了解约
		- 自动续费管理:
		  logseq.order-list-type:: number
			- 应告知用户如何在 "续费渠道" 关闭 "自动续费服务"
			  logseq.order-list-type:: number
			- 应在自己的应用提供 "自动续费管理" 入口, 用户可以 **查看 和 关闭** 自己的 "自动续费服务" .
			  logseq.order-list-type:: number
			- 应在开启 "自动续费服务" 前, 让用户同意 "自动续费协议" (以及开通的服务相关协议, 比如 "会员协议" ).
			  logseq.order-list-type:: number
		- 退款:
		  logseq.order-list-type:: number
			- 用户可以联系客服退款.
- ## 关于续费逻辑
	- 开启了自动续费之后, 能否继续购买自动续费 (包括当前渠道和之后的渠道) ? 对已有的自动续费是否会产生影响?
	  logseq.order-list-type:: number
	- 开启了自动续费之后, 能否继续购买单次卡? 对已有的自动续费是否会产生影响?
	  logseq.order-list-type:: number
	- 自动续费在续费渠道处, 是否有有效期? (比如 只能连续扣 10 年) .
	  logseq.order-list-type:: number
