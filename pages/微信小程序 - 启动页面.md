- ## 热启动进入的页面
	- A 类场景: 启动场景不带 path .
	  logseq.order-list-type:: number
		- ==保留小程序上次的浏览状态==
		- A 类场景值: [A 类场景常见场景值](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/operating-mechanism.html#_3-%E5%B0%8F%E7%A8%8B%E5%BA%8F%E7%83%AD%E5%90%AF%E5%8A%A8%E7%9A%84%E9%A1%B5%E9%9D%A2)
	- B 类场景: 启动场景带有 path .
	  logseq.order-list-type:: number
		- ==reLaunch 到对应 path 的页面==
		- 即 调用 [wx.reLaunch(Object object)](https://developers.weixin.qq.com/miniprogram/dev/api/route/wx.reLaunch.html) 方法:
			- 此方法, 会先关闭所有页面 (页面栈 + 悬垂页面) , 然后再打开指定页面.
- ## 冷启动进入的页面
	- ### 冷启动情况
		- A 类场景: 启动场景不带 path .
		  logseq.order-list-type:: number
			- 没有配置 **重启策略** , ==进入首页.==
			  logseq.order-list-type:: number
			- 配置了 **重新启动策略** .
			  logseq.order-list-type:: number
				- 若在小程序销毁后很久才启动, 将无视 **重新启动策略** , 直接 ==进入首页== .
				  logseq.order-list-type:: number
					- ==这个时间配置, 见下文 **onSaveExitState** 返回的 `expireTimeStamp`==
				- 否则, 遵循 **重新启动策略** 配置 
				  logseq.order-list-type:: number
					- ==(见下文 重新启动策略配置)==
			- ~~基础库小于 2.8.0 的用户几乎不存在, 所以不用考虑~~
		- B 类场景: 启动场景带有 path .
		  logseq.order-list-type:: number
			- ==进入 path 指向的页面.==
	- ### 重新启动策略配置
		- 有两处可以配置:
			- 配置 `app.json` 的 `window` 的 `restartStrategy` 属性 (相当于对所有页面都配置了 `restartStrategy` )
			  logseq.order-list-type:: number
			- 配置 `页面.json` 的 `restartStrategy` 属性.
			  logseq.order-list-type:: number
			- ==**页面配置** 会覆盖 **全局配置** .==
		- 取值:
			- `homePage` (默认值) : 如果从这个页面退出小程序, 下次冷启动, 将进入 **首页** .
			  logseq.order-list-type:: number
			- `homePageAndLatestPage` : 如果从这个页面退出小程序, 下次冷启动, 会立刻加载这个页面 (貌似会先展示下首页, 再跳转到这个页面), 页面路径的参数保持不变.
			  logseq.order-list-type:: number
				- ==注意: 这个对 tabBar 页面无效==
	- ### 页面状态不会保留
		- 冷启动重新打开页面时, 并不会保留退出时的状态.
			- 即 输入框中的文本内容, checkbox 的勾选状态等都不会还原.
		- ==如果需要保留, 见下文 **onSaveExitState**==
- ## onSaveExitState
	- ### onSaveExitState 的调用时机
		- 每当小程序 **可能** 被销毁之前, **页面栈栈顶** 的页面的回调函数 `onSaveExitState` 会被调用.
			- 注意: 这里说 **可能** , 微信没有明确说明具体什么情况可以被认定为 **可能** .
				- 但可以确定的是: 触发了 `onSaveExitState` , 并不意味着小程序一定会被销毁.
				- 也因此, 在小程序存活期间, `onSaveExitState` 可能会被多次调用, 以最后一次的调用结果作为最终结果.
			- 注意: `onSaveExitState` 在 [Page(Object object)](https://developers.weixin.qq.com/miniprogram/dev/reference/api/Page.html#onTabItemTap-Object-object) 中描述的是 `页面销毁前保留状态回调`不太准确:
				- 应该是 **小程序可能被销毁之前回调** .
				- 页面销毁其实就是页面卸载, 会回调 `onUnload` 函数.
		- 在某些特殊情况下 (如微信客户端直接被系统杀死), 这个方法将不会被调用
			- 因此, 下次冷启动也将无视 `restartStrategy` 的配置.
	- ### onSaveExitState 的返回值
		- `onSaveExitState` 可以返回两个字段:
			- `data` : 需要保存的数据 (只能是 **可 JSON 化** 的数据)
			  logseq.order-list-type:: number
				- 可以用于重新打开页面时, 恢复页面状态.
				- 在页面加载之后, 可以用 `this.exitState` 来获取数据.
				- 注意:
					- 这只是一个便捷的恢复页面的方式, 不要用它保存重要数据, 因为它不完全可靠 (可能会被提前清除).
			- `expireTimeStamp` : 超时时刻.
			  logseq.order-list-type:: number
				- 作用:
					- 设置 **重新启动策略** 的有效时间.
					  logseq.order-list-type:: number
					- 设置 `data` 的有效时间 (超时会被丢弃)
					  logseq.order-list-type:: number
				- 默认值:
					- 如果不返回这个值, 默认为: `当前时刻 + 1 天`
				- 注意:
					- `expireTimeStamp` 有可能被自动提前, 如 **微信客户端需要清理数据** 的时候。
	- ### onSaveExitState 示例
		- ``` json
		  {
		    "restartStrategy": "homePageAndLatestPage"
		  }
		  ```
		- 注意: `onSaveExitState` 应配合 `restartStrategy: homePageAndLatestPage` 使用, 因为只有冷启动时打开退出小程序时浏览的页面, `onSaveExitState` 才能发挥作用.
		- ``` js
		  Page({
		    onLoad: function() {
		      var prevExitState = this.exitState // 尝试获得上一次退出前 onSaveExitState 保存的数据
		      if (prevExitState !== undefined) { // 如果是根据 restartStrategy 配置进行的冷启动，就可以获取到
		        prevExitState.myDataField === 'myData' 
		      }
		    },
		    onSaveExitState: function() {
		      var exitState = { myDataField: 'myData' } // 需要保存的数据
		      return {
		        data: exitState,
		        expireTimeStamp: Date.now() + 24 * 60 * 60 * 1000 // 超时时刻
		      }
		    }
		  })
		  ```
