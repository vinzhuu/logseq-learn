- ## Distributed System
	- > 多个 **独立** 的计算机节点，通过 **网络** 进行通信和协作，对外 **共同提供某种服务** 的系统。
	- ==关键点：==
		- 独立的计算机节点：每个节点都有自己的 CPU、内存和操作系统，可以独立运行。
		  logseq.order-list-type:: number
			- ==并不要求是物理上独占 CPU、内存和操作系统 ，只要保证可以独立运行就可以。==
			- 可以是同一台物理机器上的不同进程，也可以是同一台物理机器上的不同虚拟化容器。
		- 通过网络进行通信和协作：节点之间通过网络（ HTTP、RPC、消息队列等方式）交换信息。
		  logseq.order-list-type:: number
		- 对外共同提供某种服务：多个节点共同完成某种业务，对外表现为一个整体。
		  logseq.order-list-type:: number
- ## Cluster
	- 广义：多个独立计算节点组成一个整体，对外提供服务，各个节点可以承担相同或不同的职责。
	- 狭义：多个独立计算节点组成一个整体，对外提供服务，各个节点承担 **相似** 的职责（一般就是同一个服务部署多个实例）。
		- 所谓相似：即，可以是做完全相同的事情，也可以有主从、分片、选主等分工。
		- 如：Redis Cluster 分片存储数据。
	- ==我们日常说的 **集群**，应该更多时候是指 **狭义的集群** ==
- ## 三者的区别
	- Distributed System：说的是系统架构，强调多个节点的协作。
	- Cluster：说的是部署形态，且多数时候强调各个节点 **职责相似** 。
	- Microservice：说的是应用架构风格，强调业务系统的服务拆分，实现各个服务独立开发与部署。
- ## 示例
	- | 系统架构 | 分布式系统 | 广义集群 | 狭义集群 | 微服务 |
	  | 单体应用，部署在一台服务器 | 否 | 否 | 否 | 否 |
	  | 单体应用，部署在多台服务器，通过负载均衡对外服务 | 是 | 是 | 是 | 否 |
	  | 用户、订单、支付服务分别部署，通过 RPC 通信，每个服务只有一个实例 | 是 | 可以算 | 否 | 是 |
	  | 用户、订单、支付服务分别部署，每个服务都有多个实例 | 是 | 是 | 是 | 是 |
	  | Redis Cluster，多个节点分片存储数据 | 是 | 是 | 是 | 否 |
